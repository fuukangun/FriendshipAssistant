# 送礼建议“今日不再提醒”设计

## 背景

FriendshipAssistant 在居民对话结束后检查玩家是否可以给该居民送礼，并在手动送礼模式下弹出建议界面。当前玩家关闭界面后，如果继续与同一居民对话，只要当天仍未送礼，界面就会再次弹出。

本设计包含两项相关需求：为建议界面增加“今日不再提醒”按钮，以及可选地将存储设备中的物品纳入建议和送礼流程。前者解决重复提醒问题，后者减少整理背包的操作，但可能改变原有游戏平衡。

## 目标与边界

### 目标

- 在送礼建议界面增加一个“今日不再提醒”按钮。
- 点击后立即关闭当前界面。
- 当天再次与同一居民完成对话时，不再触发该居民的送礼建议弹窗。
- 日期变化后自动恢复该居民的送礼建议。
- 状态随当前存档保存，重新载入同一存档当天仍保持有效。
- 保持现有自动送礼模式的行为不变。
- 增加一个默认关闭的 GMCM 开关，控制是否显示存储设备中的可送礼物品。
- 开启后允许玩家从存储设备页面直接选择并赠送物品。

### 非目标

- 不修改游戏原生的送礼次数、友谊值或居民数据。
- 不增加全局“暂停所有提醒”配置。
- 不改变已有关闭按钮的语义：普通关闭只关闭当前弹窗，不抑制后续提醒。
- 不改变礼物候选筛选、排序和喜好判定逻辑。
- 不在默认关闭时扫描或读取存储设备中的候选物品。

## 方案

采用现有 `GiftHistoryService` 的存档数据通道，新增独立的“今日已跳过提醒”记录。每条记录至少包含：

- 居民的稳定名称 `NpcName`
- 季节 `Season`
- 日期 `Day`

记录以居民名称索引。判断某居民是否被抑制时，只有当记录中的季节和日期与 `Game1.currentSeason`、`Game1.dayOfMonth` 同时匹配时才视为有效；旧日期记录自然失效，不需要依赖额外的跨天事件清理。

该方案复用当前存档读写生命周期：`SaveLoaded` 导入数据，`Saving` 写回数据，返回标题界面时清空内存状态。旧版本存档缺少新字段时使用空集合，保持向后兼容。

存储设备功能由独立的配置开关控制。开启后，候选工厂将玩家背包和存储设备物品分别生成候选集合，建议界面按来源分页展示。存储设备中的每个候选需要保留其实际来源容器和槽位引用，送礼时从该容器扣除一件，不能仅按物品 ID 从背包扣除。

### 存储设备范围

纳入以下原版设备：

- 普通木箱 `Chest`
- 石箱 `Stone Chest`
- 大箱子 `Big Chest`
- 石制大箱子 `Stone Big Chest`
- 冰箱和迷你冰箱 `Fridge`、`Mini-Fridge`
- 朱尼莫箱 `Junimo Chest`

默认不纳入以下特殊容器或设备：

- 梳妆台：主要存放衣物，不作为普通礼物库存。
- 自动采集器：属于产出设备，不作为玩家主动管理的通用存储设备。
- 出货箱、垃圾桶等具有特殊游戏语义的容器。
- 无法稳定暴露标准物品列表的其他模组容器。

开启后扫描存档中玩家可访问的上述容器，不限制玩家与容器的距离。朱尼莫箱按游戏原生的全局共享行为处理。该范围扩大了玩家可直接用于送礼的物品来源，因此必须在 GMCM 设置名称或说明中明确标注会影响游戏平衡性。

## 组件与职责

### `GiftHistoryData` / `GiftHistoryService`

- 扩展存档模型，保存居民的今日跳过记录。
- 提供按居民和日期判断记录是否有效的方法。
- 提供记录“今日不再提醒”的方法。
- 保留现有最近送礼记录的职责，不把跳过提醒伪装成送礼记录。

### `GiftPromptController`

- 在执行礼物候选分析和打开界面前检查今日跳过状态。
- 创建建议菜单时传入“今日不再提醒”的回调。
- 回调执行时用当前游戏季节、日期和居民名称写入跳过记录。
- 自动送礼模式不显示建议菜单，因此不调用该回调，也不受该记录影响。
- 根据 `ShowStorageItems` 配置决定是否收集存储设备候选。
- 为每个存储候选保留实际来源，以便送礼时调用统一的容器扣除流程。

### `GiftSuggestionMenu`

- 在现有物品网格和关闭按钮之外渲染一个底部操作按钮。
- 点击该按钮时调用控制器传入的回调并关闭菜单。
- 普通关闭按钮和物品选择流程保持原有行为。
- 按钮位置使用稳定的布局常量，避免候选物品滚动区域因按钮加入而变化。
- 在“背包物品”和“存储设备”两个来源页面之间提供左右切换控件。
- 存储设备页面只在 `ShowStorageItems` 开启时出现；关闭时保持现有单页背包界面。
- 两个页面分别维护滚动位置，切换页面时不改变另一页面的滚动状态。
- 存储设备页面没有候选礼物时显示空状态，背包页面仍可正常使用。

### 存储物品收集与送礼

建议增加独立的存储设备访问与候选收集边界，避免让 `GiftPromptController` 直接了解地图对象遍历细节：

- 访问器遍历符合范围的原版容器，并返回物品及其来源容器。
- 候选工厂继续复用现有的可送礼过滤、原生喜好判断和分类逻辑。
- 送礼服务根据候选来源从背包或实际存储设备扣除一件物品。
- 容器在菜单打开后可能被其他操作改变；送礼前必须重新确认来源物品仍存在且数量大于零，失败时不修改任何容器。
- 同一物品 ID 出现在多个容器时可以合并展示，但必须保留可扣除的来源集合；若不引入来源合并模型，则按来源容器分别展示，优先保证扣除准确性。

### 本地化

在 `i18n/default.json` 和 `i18n/zh.json` 中新增按钮文本：

- `ui.dismissToday`
- 英文：`Don't remind me today`
- 中文：`今日不再提醒`

同时新增 GMCM 设置文本：

- 配置键：`ShowStorageItems`
- 设置名称键：`gmcm.showStorageItems.name`
- 设置说明键：`gmcm.showStorageItems.tooltip`
- 设置名称：英文 `Show Storage Items`，中文 `显示存储设备物品`
- 设置说明：英文和中文都必须明确说明该功能“可能影响游戏平衡性”。
- 默认值：`false`

## 交互与数据流

```text
对话结束
  -> GiftPromptController.TryPrompt
  -> 居民可送礼？
  -> 今日已跳过该居民？ -- 是 --> 结束，不弹窗
  -> 分析背包候选礼物
  -> 若开启存储设备设置，分析存储设备候选礼物
  -> 打开 GiftSuggestionMenu（背包页 / 存储设备页）
       -> 选择礼物：按现有流程送礼并关闭
       -> 存储设备页选择礼物：从实际来源容器扣除一件并关闭
       -> 关闭：仅关闭当前界面
       -> 今日不再提醒：记录居民+季节+日期并关闭
```

玩家点击“今日不再提醒”后，在同一季节和日期与该居民再次完成对话，不应出现建议菜单。与其他居民对话仍按原规则判断；进入下一天或其他日期后，该居民的提醒恢复。

## 错误处理与兼容性

- 居民名称为空、日期无效等情况沿用现有服务层参数校验方式。
- 缺失或为 `null` 的旧存档字段按空字典处理。
- 同一居民当天重复点击只覆盖同一条记录，不产生重复集合项。
- 若菜单关闭或游戏状态变化导致回调无法完成送礼，跳过提醒按钮仍只影响提醒状态，不改变背包和游戏原生状态。
- 存储设备中的候选在送出前如果已被移动、消耗或容器不可用，应放弃本次送礼并保留菜单状态或显示失败提示，不得从其他位置误扣同 ID 物品。
- 访问存档中不存在、未加载或不兼容的容器时跳过该容器，不能阻止背包候选正常显示。

## 测试策略

优先补充不依赖游戏 UI 的服务层测试：

- 记录后同一居民、同一季节和日期返回已跳过。
- 季节变化或日期变化后返回未跳过。
- 不同居民的记录相互隔离。
- 导入旧数据或 `null` 数据时跳过记录集合为空。
- 重复记录不会造成行为歧义。

存储设备功能增加以下测试：

- `ShowStorageItems` 默认为关闭，关闭时不会产生存储候选。
- 开启后识别所有纳入范围的容器，排除梳妆台、自动采集器和特殊非库存设备。
- 多个容器中的物品能生成正确的来源信息。
- 从背包送礼和从存储设备送礼分别扣除正确来源中的一件物品。
- 存储物品在菜单打开后被移除时不会误扣背包或其他容器中的同 ID 物品。
- 页面切换只改变当前显示来源，并保持各页面滚动位置。
- 存储设备没有可送礼物品时，空状态不会阻塞背包页面。

补充布局测试，验证“今日不再提醒”按钮的矩形位置和尺寸位于菜单底部且不覆盖关闭按钮或滚动区域。控制器与菜单之间的回调连接通过现有测试结构或最小化可测试接口验证；不引入 Stardew Valley 运行时模拟框架。

## 验收标准

1. 手动送礼模式下，建议界面显示“今日不再提醒”按钮。
2. 点击按钮后当前界面关闭。
3. 当天再次与同一居民对话，建议界面不再弹出。
4. 当天与其他居民对话，提醒行为不受影响。
5. 日期变化后，该居民的建议界面可以再次弹出。
6. 普通“关闭”操作不会改变后续提醒行为。
7. 自动送礼模式的既有行为保持不变。
8. 旧版本存档能够正常加载。
9. GMCM 显示“显示存储设备物品”开关，默认关闭，并标注该功能可能影响游戏平衡性。
10. 开启设置后，建议界面可以在背包物品和存储设备物品之间左右切换。
11. 存储设备页面中的物品可以直接送出，并从实际来源容器扣除一件。
12. 未开启设置时，现有背包送礼流程和界面保持不变。

## 后续扩展点

本设计当前覆盖居民级、当天有效的提醒抑制，以及原版常见存储设备的候选和送礼。未来若需要“本周不提醒”“所有居民不提醒”或“仅生日提醒”等规则，应在提醒策略层增加独立状态和优先级，不复用今日抑制记录表达不同语义。

未来如果需要支持其他模组容器，应优先定义稳定的容器访问适配接口，再逐个适配；不应通过类型名称猜测或直接扫描未知对象来扣除物品。
